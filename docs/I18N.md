# Watched in other languages

Watched speaks English and 19 other languages: Spanish, French, German, Portuguese (Brazil), Italian, Dutch, Polish,
Turkish, Indonesian, Ukrainian, Japanese, Korean, Simplified Chinese, Traditional Chinese (Hong Kong and Taiwan) and
Arabic (right to left), chosen from where visitors come from (2026-11-19), then Russian, Vietnamese, Persian (right to
left) and Hindi (2026-11-21), chosen for the people English keeps away as much as for those who came (owner). The
brand ("Watched.", www.watched.earth), satellite, sensor and agency names, NORAD ids and UTC are never translated.

Three rules shaped everything here:

- **No cost and no wait.** Translations are static files in the build; nothing is translated at runtime, no service is
  called, nothing new is stored. English costs little more than before translations (measured 2026-11-19 against
  main, gzip): the first screen loads 18 files instead of 17 (the i18n core) and 134.9 kB of JavaScript instead of
  128.2; index.html is 2.5 kB larger (the boot script that picks the language and the loading screen's few words in
  every language, so a slow page speaks its visitor's language before any chunk arrives); the results and the
  time-lapse load as many files as before; all of English's JavaScript is 732 kB instead of 712 (+3 %: the catalogs
  and the switcher). Any other language is one extra chunk (all its copy, ~20–25 kB compressed) that index.html starts
  downloading in parallel with the app. `vite.config.ts` groups the i18n core into one chunk: without the groups,
  Rolldown cut the modules the first screen shares with the 15 locale chunks into seven slivers.
  Chinese, Japanese and Korean use the device's own fonts (no download); Cyrillic, Arabic and Devanagari fonts download
  only for pages that show those scripts (unicode-range), and Vietnamese ones only for Vietnamese pages (`:lang(vi)`).
- **Every language reads as if it were written for this product.** Each has a style guide (`docs/i18n/<locale>.md`:
  register, voice, glossary, grammar strategies for inserted names and counts, typography) and every string is
  reviewed against it. The voice is the English one: declarative, specific, quietly uncanny, second person.
- **It looks designed in every script.** Type, leading, tracking and label sizes are tuned per writing system
  (`html[data-script]`), not inherited from English.

## How a language is chosen

`index.html` runs `src/i18n/boot.ts` before anything else (inlined by `vite.config.ts`): `?hl=<locale>` (remembered;
`?hl=auto` forgets), then the language picked in the switcher (localStorage `watched.lang`), then the browser's
preference list, matched by `api/_lib/i18n/locales.ts` (Chinese by script: zh-CN/SG/Hans → Simplified, zh-TW/HK/MO/Hant →
Traditional; any Portuguese → pt-BR; Cantonese → Traditional Chinese, the one neighbour chosen over English; any other language we don't speak → English). It sets `<html lang dir
data-locale data-script>` and modulepreloads that language's chunk. `main.tsx` awaits `startLocale()` before the first
render, so no English flashes. The switcher changes language in place, without a reload. Its menu lists each
language by its own full name, two columns of ten on a phone and four of five on a laptop (owner, 2026-11-22).

## Where copy lives

| what | where |
|---|---|
| Locales, matching, plural categories | `api/_lib/i18n/locales.ts` |
| Numbers, counts, lists (`fmt(locale)`) | `api/_lib/i18n/format.ts` |
| Dates and relative times for non-English locales | `api/_lib/i18n/dates.ts` |
| Rich copy (numbers in mono, the serif accent, emphasis) | `api/_lib/i18n/parts.ts`, rendered by `src/i18n/Rich.tsx` |
| English copy, by namespace (the source and the type) | `src/i18n/en/<namespace>.ts` |
| A translation, by namespace | `src/i18n/<locale>/<namespace>.ts`, gathered by `src/i18n/<locale>/index.ts` |
| Share card and share page copy (app and server) | `api/_lib/i18n/card/<locale>.ts` |
| The loading screen's three strings | `src/i18n/bootText.ts` |
| Runtime: active locale, loading, switching | `src/i18n/runtime.ts` |

English is split by namespace and each namespace is imported by the code that shows it, so English copy stays in the
chunk that uses it. A namespace's key is its file name (`ns('landing', …)` lives in `en/landing.ts`).

## Writing copy

```ts
// src/i18n/en/landing.ts
import { ns } from '../runtime'
import { accent, type Rich } from '../../../api/_lib/i18n/parts'

export default ns('landing', {
  search: 'Search a place',
  hero: [['Something'], ['watched ', accent('you')], ['this week.']] as Rich[],
  sub: (days: number) => `Enter any place on Earth. See every satellite that passed over it in the last ${days} days, and the actual pictures they took.`,
})
```

```tsx
const m = useMsgs(enLanding)            // React: re-renders when the language changes
<input placeholder={m.search} />
<Rich parts={m.hero[1]} classes={{ accent: s.serif }} accentAs="em" />
```

Outside React, read `msgs(enNamespace)` at call time (never at module load). On the server, pass the messages in
(`cardMessages(locale)`).

Rules:

- **Whole sentences, never fragments.** A message is a complete phrase with its slots as function parameters; code never
  glues translated pieces together, because other languages order them differently. A sentence that mixes styles
  (a mono number, the serif place, a bold count) returns rich parts, and the translation orders them.
- **Inserted names are never inflected.** Place names, satellite names and other data are inserted as they come; each
  language writes frames that stay grammatical around an uninflected name (see its style guide).
- **Counts go through `fmt(locale).plural`** with every category the language has (Polish: one/few/many/other; Arabic:
  zero/one/two/few/many/other); a missing form is a type error. Numbers go through `fmt(locale).int / dec`, never
  `toLocaleString('en-US')` or a pinned `Intl` locale in UI code.
- **A no-break space ties a count to its noun** where the language wants it (*1 037 снимков*, *12 345 images*, *En az
  1.713*): the catalog writes it, escaped (`\u00a0`), and nothing else adds it. Every renderer keeps it: `Rich` sets a
  number as inline text, and neither satori nor the share card's canvas breaks at one (`wrap`, Chinese and Japanese
  included, which it cuts into Intl.Segmenter's words: the space is a word of its own there). A number set as a box of
  its own (an atomic inline: `<Count>`'s animated digits) is the exception: Chrome breaks a line on either side of such
  a box even against the space (Russian's *Опубликовано 1 037 / снимков.* at 360 px), so its caller sets the words tied
  to it in one nowrap span with it (`holdNum` in `src/i18n/Rich.tsx`), as it does a counter written against the number
  (Japanese *枚*, Korean *장*). English writes plain spaces there and holds nothing.
- **Write a place with its plain spaces.** The results headline keeps its serif place on one line wherever the place
  fits one, measured (`src/ui/results/wholePlace.ts`: the balance had split *New / York*, *Ciudad / de México* and
  *New / Delhi को* in every language), and lets a place too long for a line wrap inside itself. A catalog that joins a
  name's words with no-break spaces takes that wrap away and can overflow a phone's line.
- **Case is CSS's job.** Mono labels are stored in sentence case and uppercased by `text-transform` (which follows
  `lang`: Turkish i → İ). Where there is no CSS (canvas, satori), use `toLocaleUpperCase(LOCALE_INFO[l].intl)`.
  Units are the exception, in every language: `786 km`, `10 m`, `7,46 км/с` stay lowercase in a caps row (DESIGN §3).
  Write them lowercase; a unit part is kept out of the capitals by `[data-unit]`, a finished string by `withUnits`
  (DOM) or `capsExceptUnits` (canvas, satori), both from `api/_lib/i18n/units.ts`.
- **Accessible names are copy too**: aria-label, title, alt, placeholder.
- **A visual "k / n" counter goes through `system.counter(k, n, digits)`** (the gallery and the photo viewer, the pass
  pager, the time-lapse's badge and waiting line), never a slash glued in code (the computing readout's progress
  lines are whole catalog sentences and write their counts themselves): where `3 / 12` reads as a date, the
  language writes another form (Vietnamese *3 trên 12*, docs/i18n/vi.md §3.8). It returns the lead and the tail, so a
  narrow view can drop the tail. What a screen reader hears is still each screen's own sentence (*photo 1 of 40*).
  Checked in all 20 languages (2026-11-22) against the dates beside the counters: only Vietnamese writes a short date
  as d/m. The others write a month name (es fr pt-BR it nl pl tr id uk ru ar fa hi), 月日 / 월일 (zh, ko), dots
  (de: *28.10.*) or a slash date that always carries a weekday or a year (ja: *11/1(日)*, *2017/12/20*).
- **Telemetry stays English.** Analytics read the English namespace objects directly (never `msgs()`), so the admin
  page's error messages, labels and enum values do not change with the visitor's language.
- **English stays byte-identical** when code moves to catalogs: the English functions keep the exact output, including
  hand-made formats ("Sun 1 Nov", "12 min ago"); other languages take their CLDR forms from Intl (`dates.ts`).
- Caches and memos whose output contains copy are keyed by `useLocale()` / `currentLocale()`.
- Legal data attributions ("Contains modified Copernicus Sentinel data") stay in English.
- **Coordinates are international notation** ("43.4723°N 80.5449°W") in every language but one: a Vietnamese page
  writes its own hemisphere letters (`hemispheres` in `LOCALE_INFO`: B N Đ T), because there N is *nam*, south, beside
  a compass that writes north B. A place's label is data and keeps N S E W (`geocode.ts coordinateLabel`).
- **Text measured to fit is measured as drawn** where a script's letters are not one mono cell each (Devanagari's
  vowel signs, CJK's double cells, Arabic's joins): the timeline's day labels (`Timeline.tsx useLabelWidth`). Latin
  and Cyrillic keep the cell count.

## Place names

The place data is English (GeoNames' names in the offline list, the geocoders asked in English), and stays English
in the Place: the usage stats, `record_lookup`, links and shares count one town as one row in every language. On
screen, a place is named as the visitor's language names it, and a search typed that way finds it
(`src/imagery/exonyms.ts`, `src/imagery/exonymSearch.ts`):

| Italian | 901: Monaco di Baviera, Londra, Mosca, Fontana di Trevi, Striscia di Gaza | 10.6 kB | its own chunk |
| Ukrainian | 1,304: Київ, Харків, Львів, Москва, Оболонь, Газа | 17.7 kB | its own chunk |

- **Generated, never typed.** `npm run data:exonyms <GeoNames dir>` (`scripts/build-exonyms.ts`) writes
  `src/i18n/<locale>/exonyms.gen.ts` from GeoNames' alternate names; `scripts/exonyms.ts` holds the rules and the
  hand-made fixes (`OVERRIDES`, `ALIASES`). A wrong name is fixed there and the tables generated again; the offline
  list itself is not rebuilt (each rebuild of it adds ~10 MB to git history). The name is GeoNames' preferred one in the
  language, else its first plain one, else a short one; never a historic or colloquial one (Ленинград, Sài Gòn), never
  an administrative form (استان کرمانشاه, Thành phố Nam Định, Provinz Nghe An), only in the language's script, and in a
  Latin language only where it is the language's own name (München; not Bien Hoa for Biên Hòa, nor Ōsaka).
- **What each table covers, and why.** Every name ships with its language and must earn its bytes (owner rule: costs
  nothing, stays fast). A Latin table writes only the names that differ from the English, so it names towns of 5,000
  people at home, the neighbours' of 50,000, the large and widely known ones abroad (known: GeoNames has 50+ names for
  them in other languages) and the regions of home, the neighbours and a few large countries. A table in another
  script writes every name, ~12 bytes compressed each, so it names the capitals (a dependent territory's only from
  50,000 people) and the large, widely known towns abroad (~400, and by hand the ones its readers search that the
  thresholds miss: Милан, کربلا), every first-level region at home and in a few large countries (the US states, the
  UK's nations), and the home countries' towns down to a size that fits 20 kB (a chunk of its own, fetched at idle:
  `exonymTables.test.ts` holds each to it; far small states' capitals, Yaren or Majuro, are left out to make room):
  Russia's, Belarus's, Kazakhstan's and Kyrgyzstan's of 100,000+ and Ukraine's of 100,000+ in Russian; Ukraine's of
  10,000+ in Ukrainian (uk.md §4.3); Iran's, Afghanistan's and Tajikistan's of 50,000+ in Persian; India's of 100,000+
  that GeoNames names in Hindi. All of them: the curated landmarks GeoNames knows (`scripts/landmarks.ts`), the
  landing's curated places as the language's own copy names them (`places.ts`: Tschernobyl, Етна, Piramidi di Giza),
  the features at home the offline list carries (`homeFeatures`: Starnberger See, Heidelberger Schloss, Hồ Ba Bể; in a
  Latin table only those it shows under an English word), the large seas, and no countries, which the browser names
  (`Intl.DisplayNames`, as the where line does; a table's `countries` flag names a country's own label and finds it by
  search the same way, and `countryAliases` adds the names a language types for one: Белоруссия, Южная Корея). A
  country is its code's row of the offline list (kind `c`), whatever the list calls it: GeoNames' Palestinian Territory,
  Ivory Coast, The Netherlands, Turkey, where the browser says Palestine, Côte d’Ivoire, Netherlands, Türkiye
  (`LIST_COUNTRY_NAMES` in `localPlaces.ts`, fixed data a test holds to the list, says which file holds each, and names
  such a row as its country, the list's or Open-Meteo's, which names places as GeoNames does, from the first time it is
  shown, whatever files the page has read: `isListCountry`; a row named as the browser's English name without its aside
  is its country too: the list's Falkland Islands, Chromium's Falkland Islands (Islas Malvinas)). A search finds it by
  every name the page shows for it: the browser's long and short names, the one the where line shows
  (`shownCountryName`: German's pinned Palästinensische Autonomiegebiete, Hindi's अमेरिका), each also without its aside
  in brackets (Мьянма for Мьянма (Бирма)); never by an old code the browser names as its successor (CS, the list's
  Serbia and Montenegro, as Serbia). A region named like its capital has a label of its own (`#`: استان قم, Tỉnh Thanh
  Hóa), so the two rows of a search differ; a where line keeps its plain name (قم).
- **Loading, and a name that never changes.** A table of 5 kB or less would ride in its language's chunk; since the
  native review every one is larger, so each is a chunk of its own (`load` in the language's `exonyms.ts`, made by
  `tableChunk` in `src/i18n/optionalChunks.ts`): neither the first paint nor the language's chunk carries it: it is
  fetched at idle once the landing's entrance is over (`warmAfterLanding`), at boot for a link (`prefetchExonyms`), and
  awaited by everything that shows a place name first (`ensureExonyms`): a search (`searchPlaces`, which meanwhile reads
  a Latin query's own offline file and the landmarks, `prefetchLocal`, so the first search after the landing waits for
  the longer download, not both in turn: slow 3G, «Paris» typed at once shows its first row after 2.3 s in Russian and
  German, was 3.3 and 2.8 s, English 1.8 s), a pin or "my location" (`reversePlace`), a report (`runReport`, which waits
  only if it is still on its way, and for a link's country at its point too, both at once: `namesReady.ts`) and a switch
  to the language (`ready`, awaited by `setLocale`, which also looks up the country of a link's place on screen). Each
  waits 3 s at most (`EXONYM_WAIT_MS`): a table, a search chunk or a tile that never arrives (a stalled request) leaves
  the names as they came, and a download a search, a pin or a report has waited for in vain is never waited for again
  (`overdue`: a stalled search chunk held every search 3 s), nor a link's lookup by a switch after it, though either is
  used if it arrives. A prefetch's time does not count: a table asked for at idle and still on its way when the first
  search comes is a moment away, and that search waits for it. The search half (`exonymSearch.ts`, 2.1 kB) loads with
  it. A name shown before its table arrived (late, or failed to load) is kept for the rest of the page, and a link's
  name shown before its country was found stays countryless in that language (`linkedForName`; a language that has not
  shown it yet takes the answer, so a switch from Korean, whose names need no country, to Russian still says Москва): a
  name never changes once shown (owner rule). The tab's title names a place only once the table is in, or kept out
  because a name was shown without it
  (`onExonymsReady`); until then it stays as it is (a place page's static title), so its first name is its last, and
  while the app boots on a place page its place is named as its report will hold it (Pyramides de Gizeh from the start).
  A table or search chunk that fails to load never reloads the page, whoever asked for it, a switch included
  (`staleBuild.ts` reloads for any other missing chunk; Safari's error names no module, so every such download is in the
  quiet set while it runs: `quietImport`): the visitor's typing is kept. English has no table and downloads nothing for
  it: the same script files as without the tables, at the load event and at idle, and 3.1 kB more code in the shared
  chunks than before the tables (the search, the link's country and the where line's rules; measured 2026-11-22 after
  the third review, production build: 489,660 → 492,727 B gzip; 1.1 kB more since, for the fourth review (the country
  rows, of which 0.3 kB are the list's own country names, the rows that read alike, the first search's early read, the
  waits' limits and the tab's names): English's 44 script files, 683,119 → 684,185 B, measured on the merged build); a
  language with a table fetches two more files at idle (~2.5 s), and Korean, whose four names ride in its chunk, one
  (the search, 2.1 kB).
- **Search in the visitor's own names.** The table is also an index of how the language types each place (accents and
  case folded, Persian ي ك ة as ی ک ه, the non-joiner dropped, Devanagari's nukta dropped and its vowel signs kept): a
  query that is a name, starts one, or is the end of one (Hồ Chí Minh) stands for the English name the offline list
  files the place under, which is looked up in its own file and ranked as the place itself would be (the capital Hà
  Nội leads the hamlet of that name). A Cyrillic, Persian or Devanagari query is answered offline when the table knows
  the place, and goes to the network otherwise, as before. Search-only names (`~`: Sài Gòn, Питер, Kiew) find a place
  and are never shown. A name the language gives places at home and abroad finds the one at home first (`home`: Thái
  Nguyên is the Vietnamese city, not Taiyuan), and a place named exactly so at home leads every place the query only
  starts (Quận 1 before Quận 10), but a hamlet never leads a famous place abroad (Betlemme in Apulia); a town comes
  before the region the visitor reads by its name, however either was found (Huế, then Thành phố Huế), and a place named
  exactly as typed before one that only folds to it (Nha Trang, not Nhà Trắng); German's umlauts typed out are read as
  the letters (`umlauts`: Muenster, Luebeck), and an old name's landmark row (Kiev, Peking) gives way to the city the
  language names. A name two English names share (Photon's Zaporizhzhia, the list's Zaporizhzhya) is looked up under
  both, a short query keeps the home country's names before the five places it may stand for are chosen (Hà N is Hà
  Nội), and two rows that read alike within 25 km are one (a city-state and its state); so are rows of one country whose
  name and where line read alike however far apart (`distinctAsShown`: Запоріжжя · Запорізька область, Україна, the city
  and two villages of that name; Hà Nội · Việt Nam, the capital and a hamlet), the best-ranked kept, or the country
  where a country and a region read alike (Đài Loan), but never a country and a town (Джибути, the country and its
  capital, whose where line would only repeat its name); a city whose where line repeats its name is not its region's
  row, and a row on screen is never replaced. The rule that asks the network below three offline matches
  (`ENOUGH_LOCAL`) counts the places, before rows that read alike are shown as one: «Запоріж» finds the city and its two
  namesake villages, three, and stays offline as in English. English lists every row as it came. A search in a
  language with a table reads, besides the files English reads, the file of each place its names stand for (~20 kB for
  Мос, ~10 kB in English).
- **By country, and by kind.** A name applies in the place's own country (London, Ontario is never Londra), and as what
  the place is: a town's label among towns, a region's among regions (Kherson the city is never Oblast Cherson), a
  landmark's among landmarks first (`^`: the White House is Nhà Trắng, White House, Tennessee is not). A place with no
  country (a sea) is looked up among the countryless names only; a place opened from a link takes its country from the
  offline list at its point (`linkCountry.ts`: the tiles, the landmarks, and the name's own search file, which alone
  holds the regions, countries and features), so a link to London shows Londra in Italian and a link to London, Ontario
  London, and the address a search for Germany or the Gaza Strip writes names them as the search did (Deutschland, गाज़ा
  पट्टी). The South China Sea is Biển Đông on Vietnamese pages, display only, as Korean shows 동해 (owner, 2026-11-22),
  and a reef or island of the Paracels or Spratlys that the data files under another country shows no where line there
  (`contested`, still flagged to the owner; the boxes keep clear of Sabah's islands and Palawan's Balabac Strait); the
  Persian Gulf is خلیج فارس in Persian by either of the data's names. Israel's "Judea and Samaria Area" (the data's
  region for the West Bank's settlements) is named as the language names the West Bank, with no country after it (Ariel
  · Westjordanland; the guides' neutral naming, de.md and it.md §8). Every table names the time-lapse's war zones as its
  guide does (§8: Gazastreifen, Dải Gaza, गाज़ा पट्टी; Westjordanland, Bờ Tây, वेस्ट बैंक), and Crimea one way under
  each of the geocoders' names for its region (GeoNames' Crimea, Photon's "Republic of Crimea" and "Autonomous Republic
  of Crimea": Krim, Крым, کریمه, क्रीमिया), never a name that assigns it (`exonymTables.test.ts`). German writes the US
  as USA and pins Palästinensische Autonomiegebiete (de.md §6.7), whatever the browser's CLDR says.
- **The where line.** Its parts are named as the language names them (Bayern, Oblast Cherson); under a label in
  Ukrainian, Russian, Persian or Hindi script (`ownScript`), a part the language has no name for is left out rather than
  shown in Latin letters (Лондон · Велика Британія; Korean's where line stays the data's), and a landmark's "France and
  Italy" is listed in the language (Francia e Italia), and so are two US states (Arizona e Utah); a landmark's line that
  ends with another country takes that country's names (the Vatican's Roma, Italia), and one with no country is named
  if every part is (Gerusalemme). A part another follows is a town (Photon's "Odesa, Odesa Oblast" is Одеса, Одеська
  область), the last a region, and two parts the language names alike are said once; once named, the parts are one
  list in the language (Persian «، »: the 'geo' namespace's `parts`). A home region is named under the geocoders'
  other spellings of it too (`regionForms`: Vietnamese's Khanh Hoa province, Bac Ninh City, Thành phố Hà Nội), so a
  Vietnamese line shows no province in English and says a city once (One Pillar Pagoda · Hà Nội, Việt Nam). Italian
  shows every name's apostrophe as ’ (`apostrophes`). A part that repeats the label stays: it tells a city from its
  region of the same name (Санкт-Петербург · Санкт-Петербург, Россия). The share sheet's text and card still print the
  English label (the owner's call).

## Typography by script

`html[data-script]` is `latin`, `cyrillic`, `cjk`, `arabic` or `devanagari`; `src/styles/scripts.css` overrides tokens
for each, so components never special-case a language. Russian shares Ukrainian's Cyrillic faces, Persian Arabic's
(both checked letter by letter: ё ы э ъ; پ چ ژ گ ک ی, the non-joiner and both digit sets). Never set raw letter-spacing
on text that can be Arabic or Devanagari (tracking breaks Arabic's joins and cuts Devanagari's headline stroke into a
dash per letter), never fake an italic for CJK, Arabic or Devanagari (`font-synthesis-style: none`), give CJK, Arabic
and Devanagari more leading than the Latin display's 0.92, and isolate numbers inside right-to-left text. A track token
that is zero is `0em`, never `0`: components add it inside `calc()`.

Numbers follow each language (`LOCALE_INFO`): French and German put a no-break space before %, Turkish puts the sign
first (*%25*, `percentFirst`), Spanish and French group thousands with a no-break space (`group`: the sans draws Intl's
narrow U+202F at 0.1 em, so *2 330* read as *2330*). `fmt(locale).pct` formats a whole percentage. In Arabic, a
percentage or a clock with its zone that follows Arabic words is a left-to-right island (LRI…PDI in DOM-only strings,
`[data-num]` in rich parts): bidi otherwise draws *%25* and *EST 11:21*.

**Vietnamese** is Latin, but Instrument Sans, Instrument Serif and Martian Mono have none of its own letters (Ơ ư, ạ ả,
ấ ệ ộ …): left to fallback, *Việt* was V-i-t in Instrument and ệ in a system face. A word is never set in two faces, so a
Vietnamese page (`:root:lang(vi)`, the only row keyed by language) sets everything, its Latin letters and digits too, in
faces that have them all, each matched to the brand face it replaces: Noto Sans (the Cyrillic stack's, the display at
67.5 %), the Cyrillic accent's Noto Serif Display italic, and JetBrains Mono, whose cell at 108.33 % is Martian Mono's
0.65 em at 87.5 % and whose weight axis is renamed so each CSS weight draws Martian's stems (measured by
`scripts/build-vietnamese-fonts.py`, which builds the files; a label keeps the English measure). Each face takes the brand
face's vertical metrics (ascent/descent-override), so every line box and baseline is the English one; the mono's ascent
has 0.1 em more, for a stacked mark on a capital (Ấ) that an ellipsised label would otherwise cut. The display leading is
1.1× (a capital's stacked marks rose into the line above's descenders at 0.92) and the hero 0.95× to keep its column's
height. Every Vietnamese face is behind `:lang(vi)`: an English page lists none and downloads nothing new, and a
Vietnamese name on another page (the switcher's *Tiếng Việt*) is set whole in the system sans, as its Cyrillic and Arabic
names are. A Vietnamese page fetches about 127 kB of faces (Noto Sans latin 60 + Vietnamese 24, JetBrains Mono 15 + 5, the
accent 23), preloaded by the boot script for Vietnamese only, and 24 or 7 kB more only for a Polish or Czech name
(Latin Extended-A); boot waits for these, not the brand faces (`src/app/controller.ts`).

Mono labels are Martian Mono, whose space is a full 0.65 em cell: between two Arabic words that reads as a gap, so the
Arabic page's mono stack takes its spaces from a space-only face of the Arabic subset (`'Watched Arabic Space'`, no
extra download).

**Devanagari (Hindi)** was designed from specimens set next to the English (2026-11-21), in faces built by
`scripts/build-devanagari-fonts.py` from the Fontsource packages (devDependencies) into `src/assets/fonts/`:

- **Sans** (running text and the display): Noto Sans Devanagari, variable at wght 400–700 and wdth 75–100, the
  Devanagari block only (119 kB; Fontsource's file is 209 kB). The display sets it at 75%, the width of the condensed
  Instrument Sans beside it, so a headline's Hindi, Latin names and digits share one measure (`--stretch-display` is
  unchanged, and the share card's canvas, which can only ask for 75%, needs no pinned face); running text at 100%. Its
  letters are designed against Noto's Latin, whose x-height and capitals are Instrument's within 5%, so it is drawn
  as it is: the headline stroke sits between the Latin's x-height and its capitals. A single width would have saved
  50 kB and set either the hero wide beside condensed Latin or running text condensed; two files cost more than one
  with both axes.
- **Labels**: Martian Mono has no Devanagari, so Hindi words in mono slots take `'Watched Devanagari Label'` (the
  same file, full width, never under 400) at `size-adjust: 120%`: at 10.5 px the vowel signs and conjuncts blur on a
  laptop's screen, at 12.6 px they read, and the stroke sits just under the label's Latin capitals, which stay at
  10.5 px (`--fs-label` is unchanged). The mono's spaces come from the same file (`'Watched Devanagari Space'`).
- **Accent**: Devanagari has no italic. The serif is one static instance of Noto Serif Devanagari (wght 350, wdth
  87.5: the stroke and measure of Instrument Serif's italic beside it; 45 kB), upright, declared italic as Arabic's is,
  carried by the serif and the signal colour. It is as tall as the sans already, so `--accent-k: 0.93` cancels the
  1.08 that lifts English's lowercase "you".
- **Leading**: vowel signs rise to 0.9 em above the baseline (ि ी े ं) and hang to 0.37 em below it (ु ृ, stacked
  conjuncts), so `--lh-k: 1.3` (the hero 0.92 → 1.2, the headline 0.98 → 1.27) and `--lh-text-k: 1.15`. At that leading
  the tallest marks sit inside the line box, so the hero's line masks need no more room than other languages'
  (`--hl-top`). `--display-k: 0.78` keeps the hero's column (Hindi set as large reads larger, and taller); 0.86 on
  phones, whose fixed hero sizes take the factor per line (Landing.module.css, as CJK's do).
- **No tracking**: `--track-display` and `--track-label` are `0em`, and literal letter-spacing in components is
  overruled (`:where(*)`, as Arabic's): Latin mono text on a Hindi page is untracked too. The gallery's segments take
  half a character of padding each side, as CJK's do (the ी of «सभी» met the divider).
- **What it costs**: a Hindi page downloads the two files (119 + 45 kB, 164 kB), both preloaded by the boot script
  for `hi` only (`SCRIPT_FONTS` in vite.config.ts, and `loadFirstFonts` in `src/app/controller.ts`: the hero is the
  largest paint, and its accent opens the hero's last line). Nothing changes for any other language: English still
  downloads its three faces, and its landing, results and share card are pixel-identical (2026-11-21).

**The share card** follows the page in all three of its renderers (the app's DOM preview, its canvas PNG and the
server's satori card read one `CardSpec`): the headline's tracking by script (`headTracking`: −0.02 Latin, −0.015
Cyrillic, −0.01 CJK, none in Arabic and Devanagari) and its leading (`headLeading`: a Hindi headline takes HEAD × 1.3,
`HEAD_DEVANAGARI`, at a size where its taller block still fits its band, `headlineSizeDevanagari`); no tracking on a
mono row in a shaped script (`needsShaping`: Arabic, Hebrew, Devanagari and the other Indic and South-East Asian
scripts); a Chinese, Japanese or Korean headline is set by phrase (`HEAD_CJK`): each text part of the headline is one
line, never broken inside, at a size where every part fits (`headlineSizeCjk`), so the translations split their card
headlines into line-sized phrases (*この1週間、* · *衛星256基が* · *見ていた* · *Waterloo。*), and Korean keeps its words whole
(`keep-all`). In every language the size is also small enough that no piece the renderers leave unbroken (a word, a
run tied by no-break spaces, a part of a hyphenated name) is wider than the 466 px column (`headlineFits`, measured by
`api/_lib/cardMeasure.ts` in the faces' own advances and kerning, Arabic by its letters' joining forms and Devanagari by
its half forms, both in satori's faces, the widest; `npx tsx scripts/build-card-widths.ts` rebuilds the tables after a
font changes). `cardSpec` is handed the measure (`provideCardMeasure`) instead of importing it: the server card hands it
in up front, the app fetches it as its own chunk once a report is final (`src/ui/share/measure.ts`), so a search that
is never shared never downloads its tables. A place with a word too wide even at 36 px is cut short with an ellipsis. The canvas draws a Cyrillic headline in a face pinned at the page's 67.5% width (`--font-card-display`),
since a canvas can only ask for 75%. Every card's text takes a no-break space for U+202F and U+2009, which the card's
fonts lack (`cardSpaces`); `api/_lib/cardGlyphs.test.ts` renders every Latin, Cyrillic and Vietnamese language's cards,
each also with a Vietnamese and a Russian place, and fails on any character the bundled fonts cannot draw. The canvas
fetches a stack's faces family by family, each only for the characters the ones before it do not claim, so a
Vietnamese page's PNG fetches its own faces and not the brand faces behind them. The week card's chip and its scale bar
are fitted together (`summaryLookFit`).

The share card's Open Graph image, drawn on the server by satori (`api/og.tsx`), makes the same choices. Turkish and
Polish letters come from the brand faces' latin-ext cuts. Cyrillic is set in static cuts of the web's faces at the web's
widths, weights and size-adjust (`api/_fonts/*-cyrillic.ttf`, built by `scripts/backend-fonts.py`), read only for a card
that speaks Ukrainian or Russian or prints Cyrillic. Vietnamese has cuts of its web faces too (`*-vietnamese.ttf`: latin,
Vietnamese and Latin Extended-A merged, with the web's line metrics), first in every role on a Vietnamese card, as on its
page, and last on any other, where they draw only the letters the brand faces lack (Hà Nội's ộ, which sent satori to
Google Fonts). satori keeps one face per name, so every file is registered under a name of its own and each role's stack
names them in order (`cardFamily` in `api/_lib/fonts.ts`). Chinese, Japanese and Korean come
from Noto subsets fetched for each card (`api/_lib/fallbackFonts.ts`), and the card's `lang` makes Han take its
language's forms. Devanagari comes from the same loader, but as the page sets it, a face per role (`ROLE_FACES`), each
registered under the name its role's stack lists (`DEVANAGARI_NAME`): Noto Sans Devanagari condensed for the display, at
full width for the sans and, its em shrunk by 1.2, for the mono's labels (the page's size-adjust), and Noto Serif
Devanagari for the serif. Google serves named instances only, so the display is 600 where the page sets 560 and the
serif 400 where it sets 350. A Hindi card costs three style sheets and three files (the sans's shared with the mono);
satori names the danda «।» under six Indic scripts, and it joins the card's Devanagari request (`mergeShared`) instead
of fetching Bengali, Tamil, Malayalam, Telugu and Kannada subsets for one bar. satori shapes Devanagari correctly (with
HarfBuzz; Devanagari runs left to right, so its missing bidi does not matter): conjuncts (क्ष, त्र, श्र, द्ध), the
i-matra drawn before its consonant (कि, क्षत्रिय), reph over the next letter (धर्म, सार्वजनिक), nasal marks and nuktas
(उपग्रहों, ज़्यादा, ऊँचाई) came out as the browser draws them in rendered cards (2026-11-21). So Hindi links unfurl in
Hindi. Arabic is the exception: satori shapes it but has no bidirectional layout (an Arabic headline came out with its
words reversed), so a right-to-left link, Arabic or Persian, unfurls with the English card (`cardLocale` in
`api/og.tsx`); its share page is in its language, and the PNG the app saves is drawn by the browser's canvas, which lays
Arabic script out properly.

**The time-lapse video** draws its chips on a canvas too (`src/ui/timelapse/video.ts`): its mono tracking is off for a
readout in Arabic or Hindi and for any line in a script whose letters join or share a headline stroke (`joins`: Arabic,
Syriac…, Devanagari, Bengali, Gurmukhi), so a Devanagari place name is never tracked in any language.

## Right to left (Arabic, Persian)

`<html dir="rtl">` mirrors the page the way an Arabic or Persian reader expects, and leaves alone what is not text:

- **The layout mirrors.** The landing's copy sits on the right, the results dock on the left, the HUD's corners swap,
  rows read right to left, text aligns to the right. Stylesheets say this with logical properties
  (`margin-inline-start`, `inset-inline-end`, `text-align: start`, `border-start-start-radius`), which are the
  physical ones in a left-to-right page: English renders exactly as before.
- **The globe frames itself in what is left.** Every panel publishes what it covers (`store.uiInsets`) from where it
  actually is, not from the language (`ErrorNotice.tsx` is the model): the camera's lens shift follows.
- **Not mirrored:** the globe and everything drawn on it, photos and what is drawn on them (scale bar, north arrow,
  crosshair), and every time axis: the timeline, the replay scrubber, the time-lapse's years and the gallery's order
  run left to right, as clocks and charts do in Arabic (`direction: ltr` on their containers, the words inside
  isolated). Numbers, times and coordinates are isolated inside Arabic text (`[data-num]`, scripts.css).
- **Motion follows reading.** A slide that means "forward" (a panel opening deeper, a drawer) comes from the other side;
  `--dir-x` (1, or −1 in right to left, tokens.css) signs a translateX.
- **Icons that point along the reading** (back, forward, "→" in copy) flip; ones that point along a time axis or at the
  globe do not. `Glyph` marks its left and right arrows `data-reading` and base.css mirrors them with `scale` (which
  composes with a component's own rotation); a disclosure arrow inside a rotated wrapper mirrors on the wrapper instead
  (`PassList.module.css`), or an open row would point up.

How it is built: `--safe-start` / `--safe-end` (the notch on the reading's sides) and `--to-inline-end` (a scroll row's
fade) in tokens.css; the wide dock (`Sheet`) docks at the inline end and slides in from there; `Swap` multiplies its
travel by the page's direction; the landing's, the results dock's and the error notice's insets are read from their
layout boxes. The photos are a sequence: the gallery track, its rail and arrows and the viewer's filmstrip stay left to
right (the scroll code reads a forward distance), while the chips that are words move to the reading's corner and what
is drawn on the ground stays. The search field shows the native caret over Arabic (a block caret cannot sit inside
bidi text or over joined letters). Text whose direction is the visitor's, not the page's (a place name in the results'
search bar, a typed query), takes its own direction (`dir="auto"`; the field's `queryDir`, src/i18n/bidi.ts, which
also reads Persian digits right to left) but still aligns where the page starts: a physical `text-align`, because
`start` would follow the text's direction. An ellipsis then cuts the name's end, never its start. A stamp or zone inside
right-to-left copy goes through `whole()` in its isolate, or it can break at a hyphen and read out of order. The share card itself keeps its left-to-right composition in Arabic (its preview
too, so the preview and the PNG match); the Open Graph card for an Arabic link is English (see above).

`?hl=pseudo-rtl` (dev only) shows the pseudo-locale laid out right to left, to check the mirror without Arabic copy.

## Measuring

The admin page counts tabs by the language the app showed them (section 09, migration 0027) and by their browser's
first language (section 10, 0028): its primary subtag, `pt` not `pt-BR`, any language, not only ours
(`browserLanguage` in `src/lib/telemetry.ts`, sent with every batch's `ctx`; no extra request). For each browser
language it shows the share of its tabs that searched, and marks the ones with no translation (by `localeForTag`, so
`zh`, `pt`, `in` and `yue` have one) or one not listed yet: their searched share against the others' is what English
costs, language by language, and the most asked of them is a candidate for the next translation. Only the first
language is counted: a browser that lists one we speak after it gets that one, and section 09 shows it. A new locale's
code goes into `log_events`' list in a migration (`api/e.test.ts` holds the list to `LOCALES`), or its tabs record no
language.

## Adding a language

Add it to `LOCALES` and `LOCALE_INFO` (`listed: false` until it is reviewed), write `docs/i18n/<locale>.md`, translate
every `src/i18n/en/*.ts` into `src/i18n/<locale>/` (with an `index.ts` bundle and a `boot.ts` for the loading screen,
registered in `src/i18n/bootText.ts`) plus `api/_lib/i18n/card/<locale>.ts` (registered in
`api/_lib/i18n/card/server.ts`), check the pseudo-locale and each screen in the new language, then list it. Its place names, if its readers know places
by names of their own: add it to `LANGS` and `RULES` in `scripts/exonyms.ts`, generate its table, and wire its
`exonyms.ts` as the others are (in its chunk up to 5 kB, a chunk of its own above, with `ready` in its index). A new
script needs its row in `src/styles/scripts.css` (a downloaded face: a subset built by a `scripts/build-*-fonts.py`,
its first-screen faces in `SCRIPT_FONTS` in vite.config.ts and in `src/app/controller.ts`, and a look at every
`data-script` rule and every branch on the script in the card and the time-lapse video); a static accent in Chinese,
Japanese or Korean needs `python3 scripts/build-accent-fonts.py`. A Latin language whose letters the brand faces lack
takes Vietnamese's road: faces for every role behind `:lang()` (`scripts/build-vietnamese-fonts.py`), its boot wait and
preload (`SCRIPT_FONTS` in `src/app/controller.ts` and `vite.config.ts`, keyed by the language), card cuts
(`scripts/backend-fonts.py`, `cardFamily`) and its letters in `src/styles/scriptFonts.test.ts`.
